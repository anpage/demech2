# MechWarrior 2 Decompilation

This is a work-in-progress decompilation of the Windows 95 releases of MechWarrior 2 and Ghost Bear's Legacy. It aims to match the original machine code instruction for instruction. The goal is to provide a verified, workable codebase that can be studied or used as a basis for ports and mods.

This project is modeled after the [LEGO Island](https://github.com/isledecomp/isle) and [LEGO Racers](https://github.com/isledecomp/racers) decompilations.

> [!NOTE]
> This repository is a **decompilation**, not a source port: it recreates the original binaries and it only compiles for 32-bit Windows 9x. A modern, portable adaptation is in progress as a separate project, [ReMech2](https://github.com/anpage/remech2-rs).

> [!IMPORTANT]
> **The decompiled code is written with the help of an LLM,** but all contributions are empirically verified by a strict process.
> * **Deterministic scripts and tools build every function with the original compilers and compare them byte-for-byte against the original binary in CI**.
> * Faking a match by writing assembly isn't allowed. Every use of assembly is allowlisted and checked against the original.
> * [The state of every function](https://anpage.github.io/demech2/STATES.HTML) is published, including the ones not yet proven.
> * You can reproduce and verify everything with your own copies of the game and [a single command](docs/BUILDING.md#with-docker).
>
> Names and comments are derived from context and strings from the binary, and can be wrong.

The badges count functions that are verified (byte-identical or proven) out of those decompiled so far.

What counts is proof, not similarity. Every annotated function is **byte-identical** to the original's, **proven** (it is byte-identical once its stack locals are renamed or symbols are declared ahead of its unit, as a committed record says), or **unproven**, in which case its difference is classified as compiler entropy or listed with its reason. [docs/VERIFYING.md](docs/VERIFYING.md) explains the states and how to check them yourself.

The simulators of the five 3D-accelerated editions (ATI 3D Rage, S3 ViRGE, Matrox Mystique, PowerVR and 3Dfx) are built from the same simulator source, with their differences behind named features.

The remaining work is proving unproven functions and understanding the code: much of it still carries placeholder names (`FUN_10003580`, `m_unk0x04`, `g_unk0x100a00dc`) that need to be studied and replaced with meaningful names and types. Contributions are welcome.

The continuous release ([`continuous`](https://github.com/anpage/demech2/releases/tag/continuous)) carries the latest recompiled binaries from `main`, with their PDBs and progress reports.

## Building

The originals were built with Microsoft Visual C++ 4.1, 4.0 and 2.2, and the project is graded with the output of those compilers. With Docker, one command builds every binary and, given your own copies of the originals, checks every function against them:

```
docker run --rm \
	-v <path-to-source>:/demech2:rw \
	-v <build-folder>:/build:rw \
	-v <originals-folder>:/originals:ro \
	ghcr.io/anpage/demech2:latest
```

[docs/BUILDING.md](docs/BUILDING.md) has the details, and the build on Windows without Docker.

## Project Structure

- `MW2SHELL/`, `MW2/`, `NETMECHW/`, `MECH2/` - The decompiled sources of the shell, the simulator (every edition), NetMech's shell and the launcher
- `common/` - What the shell and the simulator share: Miles Design VFX's headers and portable C
- `3rdparty/` - Import libraries (`.def` files), our own DirectDraw, DirectPlay, Glide, MSI95, Miles and Smacker declarations, and the third-party code listed under "License"
- `util/` - Utility headers for decompilation
- `targets.toml` - The targets ([docs/TARGETS.md](docs/TARGETS.md))
- `vc22/`, `vc40/`, `vc41/` - The targets built with Visual C++ 2.2, with 4.0, and optimized with 4.1
- `cmake/` - CMake modules
- `tools/` - Python tools and requirements
- `tests/` - The portable C tested against the hand-written assembly
- `reccmp/` - reccmp data sources
- `docker/` - The build-and-verify image: the three compilers, MASM and CMake under Wine
- `docs/` - Documentation
- `assets/` - Progress report icons

## Contributing

Contributions are welcome. Please follow the conventions established in the codebase:

- Use reccmp annotations (`FUNCTION:`, `STUB:`, `GLOBAL:`) for all decompiled code
- Functions in a compilation unit must be ordered by their address in ascending order
- Follow the clang-format configuration
- Use NCC naming conventions (`FUN_XXXXXXXX` for unknown functions, `g_unk0xXXXXXXXX` for unknown globals)
- Keep pull requests small and focused
